# rowke（ローク）— 成長を、見えるかたちに。

子どもの絵を「上手い・下手」で評価せず、一人ひとりの **“成長の航跡（wake）”** を見つけるアート教室アプリ。
千葉工業大学「総合科学特論 web3・AI概論」最終制作（社会人受講生 FLOTAN）。

## これは何か

子どものアート教室には二つの課題があります。作品や成長が「その場限り」で消えてしまうこと。そして「子どもの絵をどう見て、どう褒めればいいか分からない」という保護者の悩みです。

**rowke** は、評価軸そのものを外しました。子どもが作品を提出すると先生が講評し、保護者がコメントで寄り添います。描いていて迷ったときは、AI講師 **「Wake先生」** が答えではなく **“問い”を返し**、視点を広げて自己決定を助けます。描いた一枚は航跡として残り、歩いて鑑賞できる **3Dバーチャル展示室** や、先生とWake先生の言葉を刻んだ **修了証** として形になります。

> 「上手い・下手」で描くのをやめる子が、自分の世界を守り、描き続けられるように。

## 主な機能

- **作品ギャラリー＋講評**：先生の講評、保護者のコメント
- **Wake先生（AI）**：点数でなく“問い”を返す、視点を広げる対話
- **3Dバーチャル展示室**：歩いて鑑賞、近づくと講評や「みんなの声」が現れる
- **修了証**：代表作・在籍記録に先生とWake先生の言葉を刻む（譲渡不可のSBTをイメージ）
- **派生**：Wake Path（志望校レベル別の合格ライン・毎日の記録）／美術科受験ナビ（内申・選考シミュレーション）

## 設計思想（失敗から生まれた芯）

当初、Wake先生は質問に「答え」を返していました。しかしそれでは子どもの考えは広がらなかった。**答えを渡すより、対話しながら“問い”を返すほうが子は考え始める** ——この気づきから、rowke の中核設計が生まれました。

## 使用技術

| 領域 | 技術 |
|---|---|
| フロント | HTML / CSS / Vanilla JS（単一ファイル構成） |
| 3D | Three.js |
| AI | Google Gemini 2.5 Flash（講評・対話） |
| データ | Firebase Realtime DB（書き込みはサーバーAPI経由＋先生PIN照合）、Supabase（会話履歴） |
| ホスティング | Vercel |

書き込みは全て `/api` 経由、機微データは先生PIN、秘密鍵は環境変数で管理。

## 作り方

実装は **AIエージェント（Claude Code）に「何を作るか」を指示して構築**（手書きコード0行・約115コミット・実働およそ80時間）。
「AIに書かせること」と「何を作るかを決めること」は別の仕事、という前提で進めました。
