# ぺんぎん展示室（氷の国 3Dバーチャル展示室）設計ドキュメント

作成日: 2026-07-11
状態: 設計確定（実装計画は次段階）

## 1. 目的

千葉工業大学 web3・AI概論の最終発表会で、参加者が各自の「プロダクト掲示ポスター（A4）」を提出すると、**氷の国の3Dバーチャル展示室**に自動で額装展示され、みんながブラウザで歩いて鑑賞できるアプリ。rowke の `art-feedback/gallery.html` を土台に、単体アプリとして新規構築する。

**成功基準**
- 参加者がPDF/画像を提出すると、数秒で氷の円形回廊に額が追加される
- 30〜60人が同時にブラウザで入って鑑賞でき、当日落ちない（＝鑑賞が本質、演出は付加価値）
- 授業後に主催者が受付を締め、閉室できる

## 2. スコープ / 非スコープ

**スコープ**
- 氷の円形回廊の3D展示室（Three.js）
- A4ポスター提出（PDF/画像）→ ブラウザ内で画像化・リサイズ → Firebase Storage 保存
- メタ情報（名前・プロダクト名・リンク・見てほしいポイント・画像URL）を Realtime DB 保存
- 近づくとキャプション表示＋リンクを別タブで開く
- 演出：オーロラ・雪・ペンギン・苺投げ
- 管理：受付ON/OFF、展示の削除、閉室
- 軽量モード（演出を減らす）トグル

**非スコープ（今回入れない／将来）**
- リアルタイム・プレゼンス（他人のアバターが見える／苺が飛び交う）
  - ただし「あとから足せる」拡張点として設計を汚さない形にとどめる
- 認証・ログイン（使い捨て前提で付けない）
- 既存 rowke データへの一切の変更（`penguin/` パスに隔離）

## 3. アーキテクチャ

**技術スタック**
- フロント: 単一HTML＋Vanilla JS（バンドラーなし）
- 3D: Three.js（CDN、rowke gallery.html と同じ unpkg three@0.160.0）
- PDF→画像: PDF.js（CDN、ブラウザ内で1ページ目をレンダリング）
- 画像保存: **Firebase Storage**（rowke-app プロジェクトの既存 storageBucket を流用、`penguin/` 配下）
- メタ保存: **Firebase Realtime DB**（`penguin/exhibits` 配下）
- ホスティング: Vercel（新規プロジェクト）

**データの流れ**
- 提出（書き込み）: クライアント → 画像化・リサイズ → Storage へ upload → 返ってきたURL＋メタを DB へ push
- 鑑賞（読み取り）: クライアント → DB `penguin/exhibits` を購読 → 額を生成 → 各額の画像URLを近い順に読み込み
- 管理（削除・受付ON/OFF）: 主催パスコードで管理UIを開き、DB を更新／該当 exhibit を削除

**セキュリティの割り切り（使い捨て・誰でも提出=A）**
- 認証なし。荒らしは「削除＋受付停止＋事後に閉室」で対応
- `penguin/` パスに隔離し、既存 rowke データと分離
- Firebase Storage/DB ルールは `penguin/` のみ緩く許可（授業期間限定）。授業後にルールを閉じる or デプロイ削除
- ファイル形式チェック（PDF/PNG/JPGのみ）、サイズ上限 **15MB**、長辺2000pxに自動リサイズしてから保存

## 4. データモデル（Realtime DB）

```
penguin/
  config/
    submissionsOpen: true|false     # 受付ON/OFF
  exhibits/
    <pushId>/
      productName: string           # プロダクト名
      author: string                # 名前
      link: string                  # リンク（任意・httpsのみ表示）
      highlight: string             # 見てほしいポイント（任意）
      imageUrl: string              # Firebase Storage の公開URL
      ts: number                    # 提出時刻
```

Storage: `penguin/<pushId>.<ext>`（表示用にリサイズ済みJPEG/PNG）

## 5. 展示空間（氷の円形回廊）

- 中央に大きな氷山（目印）。周囲を円形回廊がとりまく
- ポスターは A4縦の氷フレームで、円周上に等間隔・内向き配置
- 提出数 N に応じて半径を自動調整（例: 半径 = max(基準, N × 間隔 / 2π)）→ 30〜60でも破綻しない
- 内装: 凍った床（うっすら反射）、遠景の氷山、舞う雪（パーティクル）、空にオーロラ（緑〜青紫のゆらぎ）
- ペンギン: 低ポリ、InstancedMesh で多数配置、時々よちよち歩く/向き変え
- 新着演出: 額が追加された瞬間に光が差す

**操作（rowke踏襲）**
- PC: ドラッグで視点、WASD/矢印で移動
- スマホ: ドラッグで視点、「進む」ボタン
- 常に中央の氷山が目印

**軽さ**
- ペンギン InstancedMesh、雪パーティクル、遠景板ポリ
- ポスター画像は近い額から順に遅延読み込み
- 軽量モードトグル: ペンギン/雪/オーロラを削減

## 6. 提出フロー

「＋ ポスターを出す」ボタン → フォーム:
1. ファイル（PDF または 画像 PNG/JPG）　注記: 「**15MBまで**」
2. 名前
3. プロダクト名
4. リンク（任意）
5. 見てほしいポイント（任意）

「展示する」→ PDFなら1ページ目を画像化 → 長辺2000pxにリサイズ → Storageへupload → メタをDBへpush → 数秒で回廊に額追加（新着演出）。同一人物の複数提出可。受付OFF時はフォームを無効化しメッセージ表示。

## 7. 鑑賞体験

- 額に近づくとキャプションがふわっと表示: **プロダクト名 / 名前 / 見てほしいポイント**
- 「リンクを開く 🔗」ボタン（別タブ、httpsのみ）
- 離れると引っ込む。スマホはタップで開閉
- 🍓 苺を投げる: ボタン/クリックで視線方向へ苺が放物線で飛び、着地して少し弾む（自画面演出。低ポリ粒、多数でも軽い）

## 8. 管理・当日運用

- 管理UI: 主催パスコードで開く（軽い合言葉。認証というより誤操作防止）
  - 受付ON/OFF切り替え（`penguin/config/submissionsOpen`）
  - 展示一覧＋削除ボタン（該当 exhibit と Storage画像を削除）
- 閉室: 授業後に受付OFF＋「閉室モード」表示、もしくは Vercel デプロイ削除
- グレースフルデグレード: 画像URL参照でDBは軽い／重い端末は軽量モード／プレゼンスは非搭載なので同期起因の落ちはなし

## 9. 同時接続の見立て（30〜60人）

- 今回はプレゼンス非搭載のため、各クライアントは DB `penguin/exhibits`（テキストのメタのみ、数十KB規模）を購読するだけ。画像はStorageからHTTPで個別取得（CDN配信）
- 同時60人でもDB購読は軽量。ボトルネックは各自の端末描画と会場回線
- Firebase無料枠の同時接続上限（100）にも収まる。※将来プレゼンスを足す場合は要負荷テスト

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| 会場Wi-Fiが弱い | 画像は近い順に遅延読み込み／軽量モード |
| 重い端末で60体描画 | InstancedMesh・軽量モード・遠景簡略化 |
| 荒らし投稿 | 削除ボタン・受付OFF・事後閉室・形式/サイズ制限 |
| 大きすぎる画像 | 15MB上限＋長辺2000px自動リサイズ |
| 既存rowkeへの影響 | `penguin/` パスに完全隔離 |

## 11. ファイル構成（予定）

- `penguin-gallery/index.html` — 単一HTML（3D展示＋提出＋鑑賞＋苺）
- `penguin-gallery/admin.html` — 管理（受付ON/OFF・削除）※ index内モーダルでも可
- Vercel 新規プロジェクトとしてデプロイ
