# Wake Path（デッサン専用トレーニングアプリ）設計

作成日: 2026-06-15
アプリ名: **Wake Path**（プロジェクト識別子・Firebaseルートは `dessin`）
位置づけ: rowke（art-feedback）の派生・独立アプリ。第8回課題「プロダクト v4」

## コンセプト

Wake Path は、デッサンを通して「見る力」と「描く力」を育てる、デッサン専用トレーニングアプリ。

Wake には「航跡（船が進んだあとに残る跡）」と「目覚める・気づく」の二つの意味がある。描いた線、消した跡、迷った時間、観察の記録——それらはすべて、自分の目で見て自分の手で進んだ証。Wake Path は、描く人の後ろに残る航跡を記録し、次の一歩へ導く。

AI先生「Wake先生」は正解を一方的に教えるのではなく、作品の中の成長の跡を見つけ、次に見るべきポイントをそっと示す。一枚ごとの評価だけでなく、過去作と比較しながら、その人だけの上達の道筋を可視化する。

## 目的

中高生の美術系受験生が、**先生不在でもデッサンをどんどん進められ**、AIエージェント「Wake先生」が提出を見て課題を調整しながら**基礎から志望校合格レベルまで導く**。先生は空いている時に手描き添削を返し、生徒はそれを見ながらWake先生と対話してさらに高めていく。継続できる仕掛けを備える。

## 対象ユーザー

- 生徒：中高生（中1〜高3）、美術系受験を目指す
- 先生：1名（PIN認証）。志望校情報の入力と手描き添削を担当
- 少人数運用

## コアループ

```
AIが課題ドラフトを提案（過去の弱点＋志望校基準＋残り時間で調整）
   ↕  先生がAIと相談しながら課題を調整・確定（または先生が手動で作成）
課題を生徒に提示（制限時間つき＝必須）
   ↓
生徒がデッサンを描いて写真で提出
   ↓
AIが画像をルーブリック採点＋講評＋合格ギャップ＋次の課題（その場で対話可）
   ↓ （先生が空いている時）
先生が画像に手描き添削＋コメントを返す
   ↓
生徒が添削を見ながらAIと対話 → 次の課題へ
   ↓
毎回違うモチーフを積み上げ、成長グラフで経過観察
```

毎回違うモチーフを積み上げる方式。AIは直近の低スコア軸（弱点）と志望校基準を見て次の課題を寄せる。**課題はAIと先生の協働で決める**（AIが提案→先生がAIと対話しながら微調整・確定、または先生が直接作成）。**制限時間は必須**（時間どおりに仕上げる訓練は受験で重要）。

## アーキテクチャ（案A：rowkeインフラ流用の独立アプリ）

```
[ブラウザ] ──読み取り──→ Firebase RTDB（rowke-app / ルート dessin/） ※ .read:true / .write:false
[ブラウザ] ──書き込み──→ Vercel /api/db ──(firebase-admin)──→ RTDB
[ブラウザ] ──AI──→ Vercel /api/ai （Gemini Vision：課題生成・採点・対話）
```

- 新Vercelプロジェクト `dessin`、単一HTML＋`/api/*`
- 最初からセキュア構成（書き込みはAPI経由のみ、先生操作はPIN必須）＝rowkeセキュリティ第2弾の学びを最初から適用
- Firebaseは `rowke-app` を流用し、ルートキー `dessin/` で分離（新規プロジェクト作成不要）
- 環境変数も流用：`FIREBASE_SERVICE_ACCOUNT` / `FIREBASE_DB_URL` / `GEMINI_API_KEY` / `TEACHER_PIN`

## データ構造（`dessin/`）

```
dessin/
  students/{studentId}
    name, grade(中1〜高3)
    targetSchool      : 志望校名
    examDate          : 受験時期
    examInfo          : 出題傾向・合格基準（先生が入力＝AIの判断基準で最優先）
    level             : 初級 / 中級 / 受験直前
    createdAt
    streak            : { count, lastSubmitDate }   ← 連続提出
    badges            : { badgeKey: ts, ... }
    bestScores        : { proportion, volume, texture, composition, observation,
                          space, light, structure, process }  ← 自己ベスト（9軸）

  assignments/{assignmentId}
    studentName
    motif, focus, stage(基礎/応用/実戦)
    timeLimit         : 制限時間（分）※必須
    origin            : 'ai' | 'teacher'      ← 提案元
    aiDraft           : AIが最初に出したドラフト（参考保持）
    teacherChat       : [{ role:'teacher'|'ai', text, ts }]  ← 課題決めの相談ログ
    status            : 'draft' | 'published'  ← published で生徒に提示
    ts

  submissions/{submissionId}
    studentName
    assignmentId  : 紐づく課題
    assignment    : { motif, focus, stage, timeLimit }  ← 提示された課題のスナップショット
    imageBase64   : 提出デッサン写真
    ts
    aiReview      : {
                      scores: { proportion, volume, texture, composition, observation,
                                space, light, structure, process },  ← 各1〜5（9軸）
                      comment,
                      passGap,            ← 合格ラインまであと何が足りないか
                      nextAssignment
                    }
    aiChat        : [{ q, a, ts }]
    teacherReview : { annotatedImage, comment, ts }   ← 任意。先生の手描き添削
```

### ルーブリック9軸（受験デッサン基準）

| キー | 軸 | 見る内容 |
|---|---|---|
| proportion | 形・プロポーション | 比率、角度、傾き、左右差 |
| volume | 量感・立体 | 面、明暗、丸み、厚み |
| texture | 質感・固有色の描き分け | 金属、紙、布、木、石膏など質感の違い／固有色（実際の色）を無彩色の明度に置き換えられているか。目を細めると細かな色より大まかな明るさが優先される——各色を大きく三段階程度の明度グループに整理できているか |
| composition | 構図・画面構成 | 配置、余白、見せ場、密度の配分 |
| observation | 観察・描き込み | 情報量、細部観察、粘り、エッジの描き分け |
| space | 空間把握 | 奥行き、接地、前後関係、パース |
| light | 光源理解 | 光・影・反射光・投影の一貫性、階調の幅 |
| structure | 構造理解 | 見えない内部形態、軸、骨格 |
| process | 制作プロセス | 大づかみ、修正力、全体管理（描き進め方） |

`students.bestScores` と `submissions.aiReview.scores` はこの9キーで統一。

## 画面構成

1. **きょうの課題**：先生が確定した課題（モチーフ・狙い・段階・**制限時間**）を提示 →「描いたら写真をアップ」。ログインボーナス（ストリーク表示＋AI/先生からの一言）もここ。タイマー付きで取り組める
2. **提出＆AI講評**：写真提出 → AIがその場で9軸採点・講評・合格ギャップ・次の課題。下で対話。自己ベスト更新時は演出
3. **これまで（経過）**：提出の時系列カード＋成長グラフ（9軸の推移）＋合格ライン進捗バー＋獲得バッジ。先生添削済みはバッジ表示
4. **先生モード（PIN）**：生徒プロフィール編集（志望校・基準）／**課題づくり：AIが提案→AIと相談して微調整→確定して生徒に提示**（または手動作成）／未添削の提出一覧 → 画像に手描き添削＋コメント

## AI設計（/api/ai、Gemini Vision）

4つの役割（アクション）:

- `assignmentDraft`：生徒の level・直近スコアの弱点（9軸）・examInfo・examDate までの残り時間から、次の課題ドラフト（motif/focus/stage/**timeLimit＝必須**）を生成。カリキュラム3段階（基礎→応用→実戦）を踏まえる
- `assignmentChat`（先生のみ・PIN）：先生が「もっと質感重視で」「制限時間を90分に」などとAIに相談し、課題を一緒に詰める。確定すると assignments に published で保存
- `review`：提出画像を見て、受験基準の**9軸**を1〜5で採点し、講評・**合格ギャップ（あと何が足りないか）**・次の課題を返す。examInfo を最優先の判断基準にする。子ども安全ガード（rowke chat と同じ：深刻な相談は人間へ橋渡し、個人情報を聞かない）を適用
- `chat`：その提出について生徒と対話。aiReview と（あれば）teacherReview を文脈に含める

Gemini は thinkingBudget:0＋モデルフォールバック（2.5-flash → 2.5-flash-lite）＋safetySettings を rowke と同様に設定。

## 先生の手描き添削（PIN）

- 生徒のデッサン画像を背景に、素のCanvasで赤ペン描画（線・丸）＋取り消し/全消し
- 描画を画像に合成して `annotatedImage`（PNG）として保存＋コメント
- 先生のみ（PINヘッダ）。未添削提出の一覧から処理

## 継続の仕掛け

- **連続提出ストリーク＋ログインボーナス**：連続提出日数を表示。日付が変わって初回アクセス時に AI（先生）からの今日の一言・励まし
- **マイルストーン・バッジ**：累計提出数（5/10/30…）や「初めて明暗で5点」など達成でバッジ獲得
- **合格ライン進捗バー**：志望校の合格レベルに対する現在地（5軸平均など）をバーで表示
- **自己ベスト更新の演出**：ルーブリック点が自己ベスト更新で「自己ベスト！」＋紙吹雪（GSAP不要、軽いCSS/canvas演出）

## エラー処理

- AI/書き込み失敗時はクライアントで alert 表示。読み取りは直接続のため画面は壊れない
- `/api/ai`・`/api/db` は try/catch で 500 と `{error}`。PIN不一致は 403

## 検証（受け入れ基準）

- 生徒：課題提示 → 写真提出 → AI採点・講評・合格ギャップ・次課題 → 対話、が動く
- 経過：時系列＋成長グラフ＋進捗バー＋バッジ＋ストリークが表示・更新される
- 先生（PIN）：志望校情報の入力、手描き添削＋コメントの返却ができる
- ブラウザから直接DB書き込みが PERMISSION_DENIED
- PINなし/誤PINで先生操作が 403
- 自己ベスト更新・バッジ獲得・ストリーク加算が正しく発火

## やらないこと（YAGNI / 次フェーズ）

- 読み取りの閲覧制限（`.read:true` のまま。次フェーズで認証）
- 同じ1枚を描き直して磨くモード（今回は「毎回違うモチーフ積み上げ」型に集中）
- 決済・複数教室・保護者ダイジェスト

## 制約遵守

- フロントは単一HTML＋CDN（新規JSライブラリ追加なし。描画・演出は素のCanvas/CSS）
- 秘密情報は環境変数。PIN・鍵はコード/リポジトリに書かない
